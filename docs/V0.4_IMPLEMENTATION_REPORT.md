# YLSB v0.4-rc2 実装レポート

v0.4-rc2 は、v0.4-rc1 の評価 policy (`YLSB-v0.4-rc1`) を維持したまま、生成 engine と Candidate Planner の現行実装から証拠を再生成する release です。v0.3 の frozen/raw/normalized/derived tree と、公開済み rc1 tag の履歴は変更しません。

## 再生成の正典

```sh
python3 -m pip install -r requirements-v04.txt
python3 tools/regenerate_v04.py
python3 tools/regenerate_v04.py --check
```

`regenerate_v04.py` は一時 tree で migrate、v2 regrade、calibration、planner、schema mirror、manifest を生成してから `results/v0.4-rc1/` を置き換えます。`--check` は同じ生成を一時出力へ行い、差分があれば非 0 で終了します。入力 tree は読み取り専用です。

## 生成物と provenance

- `results/v0.4-rc1/normalized/` — normalized corpus v0.2 と現行 Candidate Planner 出力
- `results/v0.4-rc1/derived/` — v0.4 policy による regrade、calibration、比較表
- `results/v0.4-rc1/derived/v0.4-rc1-implementation-report.md` — 生成時の件数と schema/freshness checks
- `results/v0.4-rc1/schema/` — canonical schema の release mirror
- `results/v0.4-rc1/manifest.json` — generator、policy、fixture、grader、planner、registry、入力 corpus の content hash と record counts

manifest は生成時刻や毎回変わる HEAD を含めず、同じ入力とソースから同じ bytes を得られる content identity を記録します。planner の候補はすべて `prediction_status: predicted` とし、observed corpus と混同しません。

## 検証結果

生成時に次を自動検証します。

- v0.4 fixture は Core 28 / Sentinel 4 として検証される。
- normalized JSONL、derived verdict JSONL、planner JSON は Draft 2020-12 schema を通過する。
- normalized corpus の file/record counts と hash が manifest に一致する。
- `--check` の再実行は zero-diff である。
- v0.3 protected baseline は generator の入力として保持され、書き換えられない。

具体的な観測値と regrade の詳細は [`results/v0.4-rc1/derived/v0.4-rc1-calibration.md`](../results/v0.4-rc1/derived/v0.4-rc1-calibration.md) と [`results/v0.4-rc1/manifest.json`](../results/v0.4-rc1/manifest.json) を正とします。policy の threshold は calibration 用であり、正式な performance slot を新規測定なしに確定しません。
