# YLSB v0.4-rc1 設計計画

## 調査所見

- v0.3 は `results/v0.3/` 以下に frozen、normalized、derived を持ち、6モデル・Core 28・Hard Sentinel 4・API smoke 10 の観測を保存している。
- v0.3 の historical gate は Core 全件を分母にしていた。v0.4 は fixture metadata の `tier` と `gate_roles` を参照し、invalid fixture と protocol/serving health を別に判定する。
- GPT-OSS の空応答は16件、`requires_rerun` は15件、invalid fixture との重複は1件である。raw flag と capability 分母を混同しない。
- baseline HEAD は `3b36e5d3d74cd40c9dfadf048702411ff4278796`。この作業では tag、release、push を実施しない。

## Architecture

```text
v0.3 raw/normalized (immutable)
        │  adapter: source fixture identity + raw observation
        ▼
v2 grader (5 dimensions + rerun) ── explicit v0.4 fixture metadata
        │
        ├── versioned policy engine (v0.3 compatibility / v0.4 rc1)
        ├── observed performance aggregation (phase/point/lane/context)
        └── v0.2 normalized derived corpus → regrade → report
```

`fixtures/v0.4-rc1/` が v0.4 の入力であり、`ume/`、`take/`、`matsu/` の既存 fixture を暗黙に v0.4 として扱わない。v0.3 source identity、v0.4 fixture identity、grader identity は出力の別フィールドに保存する。

## 要求チェック

### P0

- v0.3 protected tree の baseline SHA-256を `fixtures/v0.3-baseline-hashes.json` に保存。
- Core 28 / Sentinel 4 / API 10 の総数、全順列、unique solution、numeric/JSON gold を `validate-fixtures` で検証。
- `grade_v2` は answer、strict format、non-empty、protocol、serving、requires_rerun を独立保存。
- v0.3 policy は historical gate detail/label/pass を再計算して比較できる。

### P1

- v0.3 observation → v2 grader → explicit fixture metadata → v0.4 policy の純粋 adapter。
- normalized corpus v0.2 に5 dimension、fixture identity、grader identity、provenanceを保存。
- performance は入力 bundle の original-run R0 TG128 を repeat 平均し、Fastest Useful の候補と正式 slot 未検証を分離。

### P2

- generic importer、schema v0.2、hardware/model/runtime registry、v0.2 corpus を追加。

### P3

- hardware compatibility、RAMを含むfit判定、role付き S/F/L/D/X planner、observed outcomeを受ける境界探索を実装。

### P4

- calibration、migration、implementation report、import → regrade → report のE2E手順を保存。
- 60/70/80%は sensitivity の比較値であり、恒久 threshold は確定しない。
